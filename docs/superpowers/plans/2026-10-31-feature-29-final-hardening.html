Decisions the plan makes (veto any before "Ready for feature 29").

  1. Must do (contract and defects): global JSON error and 404 handlers, double-submit guard on every mutating form, security regression suite, automated accessibility and responsive checks, dependency fixes, cleanup, ten-run script, checklists.
  2. Should do (lowers the cost of any next sprint): one http/ module for IDs and role guards, one lib/format.ts, startup config check, root npm run check, and docs/architecture.md plus short decision records.
  3. Time-boxed spike, default ON: run server tests in their own database schema (test_suite), rebuilt each run. Go only if all tests pass three times in a row; otherwise it is reverted and documented. This stops tests polluting the development database.
  4. Pure file moves, default ON, done last: loose server files into feature folders, and client components into folders by area. Moves only (git mv plus import fixes, no behavior change), so the diff is reviewable as renames and the tests prove nothing changed.
  5. GitHub Actions workflow, default OFF. A ci.yml that runs npm run check on pull requests would run on your GitHub the moment it is merged. You said to leave your GitHub alone, so it stays out unless you say yes; the plan lists the file so you can add it yourself.
  6. New dev dependency: @axe-core/playwright (pinned 4.10.2) for automated accessibility checks. Serious and critical findings fail the test; lesser ones are reported, not blocking.
  7. Not doing: a design-system rewrite, a router library, an ORM abstraction, a permissions framework, full-text search, a general rate limiter. None has evidence of need; the architecture doc names the seam where each would go.
